# A35 Group

This is the group of APIs between
the [S01 - Consultation Service](../services/core/S01_Consultation_Service.md)
and [S18 - Forwarded Partner Selection Service](../services/core/S18_Forwarded_Partner_Selection_Service.md)

This API consists of 2 API(s).

## A35a

**Direction:** S01 sends to S18.

This API is based on RabbitMQ, with JSON payloads.

The API has the following events.

### A35a Event: `need_forwarding`

Fired when S01 needs forwarding
but did not yet know which partner
to forward the conversation to.

Message body format:

```ts
{
    "event": "need_forwarding",
    "content": {
        "conversation": {
            // This follows S01's database schema
            "id": string,
            "customer_id": string,
            "status": string,
            "partner_id": string,
            "customer_satisfaction": number,
            "summary": string
        }
    }
}
```

## A35b

**Direction:** S18 sends to S01.

This API is based on RabbitMQ, with JSON payloads.

The API has the following events.

### A35b Event: `forwarded_partner_selection_finished`

Message body format:

```ts
{
    "event": "forwarded_partner_selection_finished",
    "content": {
        "conversation_id": string,
        "status": "success or error",
        "message": string | null,
        "selection": {
            "partner_id": string,
            "partner_name": string
        } | null
    }
}
```

On `status == "success"`, `message` could be `null`,
and `selection` can be either the information
of the selected partner, or `null` if the
partner to forward can't be figured out from
the current context of the conversation.

On `status == "error"`, `selection` must be `null`,
and `message` must indicate the error. It could
be `str(e)` with `e` being the `Exception` instance
that was the culprit.
