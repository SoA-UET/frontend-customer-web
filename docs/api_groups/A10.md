# A10 Group

This is the group of APIs between
the [Core's Consultation Service](../services/core/S01_Consultation_Service.md)
and [Partner's Consultation Service](../services/partner/S13_Partner_Consultation_Service.md)

This is a cross-system API that communicates over the Internet between Telcenter Partner and Telcenter Core systems (through
an invisible gateway, so let's assume direct communication
via RabbitMQ)

This API group consists of 2 API(s).

## CRITICAL NOTES

### Real-time Audio Streaming

Real-time audio is streamed using RabbitMQ messages.
Each audio message carries a **single fixed-duration PCM frame**.

Audio is unidirectional per event, but the same event structure is used in both directions.

Audio format:

- Encoding: PCM (signed integer)
- Endianness: Little
- Sample rate: 16000 Hz
- Channels: 1 (mono)
- Sample width: 16-bit (int16)
- Container: Raw PCM (no WAV header)

This format is chosen because it is trivial to generate, decode, and play on both browsers and backends.

Frame size:
- Each audio frame represents 20 ms of audio.
- Calculation:
    - 16,000 samples/sec × 0.02 sec = 320 samples
    - 320 samples × 2 bytes = 640 bytes per frame
- So, each audio chunk MUST be exactly 640 bytes

## A10a

**Direction:** S01 (Core) → S13 (Partner)

This API is based on RabbitMQ.

This API has the following methods and events.

### A10a Event: `consultation_request`

This method is called by S01 (Core) to send a consultation request to S13 (Partner).

Request body format:

```ts
{
  "method": "consultation_request",
  "params": {
    "partner_id": string, // ID of the partner to which this request is sent
    "customer": {
        "id": string, // unique customer ID assigned by Core
        "name": string
    },
    "conversation": {
        "id": string, // unique conversation ID assigned by Core
        "title": string, // title of the conversation
        "customer_satisfaction": number, // customer satisfaction score (1-5)
        "summary": string // brief summary of the conversation
    },
  },
  "id": string // unique request ID
}
```

Response body format:

```ts
{
    "id": string, // the corresponding request id
    "result": {
        "status": string, // "success" or "error"
        "content": any // the return value of the called method"
    }
}
```

On success, the content's format would be the string `"OK"`.
This indicates that the consultation request
has been acknowledged by S13 (Partner), but
there has been no action taken yet (i.e. no human
agent taken over the conversation yet).

On failure (`status == 'error'`), the content would
reflect what is going on. If the failure is
caused by some `Exception`, the content should
be `str(e)` with `e` being the `Exception` instance
that was the culprit.

### A10a Event: `call_start`

This event is emitted by S01 (Core) to notify S13 (Partner)
that the customer is about to start a voice call on
this conversation.

Message body format:

```ts
{
  "event": "call_start",
  "data": {
    "partner_id": string, // ID of the partner
    "conversation_id": string // ID of the conversation
  }
}
```

### A10a Event: `call_end`

This event is emitted by S01 (Core) to notify S13 (Partner)
that the customer has ended the voice call on
this conversation.

Message body format:

```ts
{
  "event": "call_end",
  "data": {
    "partner_id": string, // ID of the partner
    "conversation_id": string // ID of the conversation
  }
}
```

### A10a Event: `audio_start`

This event is emitted by S01 (Core) to notify S13 (Partner)
that an audio stream transmission process is starting.

This means the user has unmuted his microphone and
is about to speak (the frontend is going to send
audio data recorded in real-time).

This event can only be emitted if the conversation
status (in Core's Consultation Service's database)
is `HUMAN_AGENT_CALLING` (i.e. after forwarding
is successful and the human agent has picked up the call).

Message body format:

```ts
{
  "event": "audio_start",
  "data": {
    "partner_id": string, // ID of the partner
    "conversation_id": string // ID of the conversation
  }
}
```

### A10a Event: `audio_chunk`

This event is emitted by S01 (Core) to transmit
a chunk of the audio data to S13 (Partner).

Each event/chunk carries exactly one PCM frame
(20 ms).

Message body format:

```ts
{
  "event": "audio_chunk",
  "data": {
    "partner_id": string, // ID of the partner
    "conversation_id": string, // ID of the conversation
    "audio_data": string // raw PCM audio data (640 bytes) base64-encoded
  }
}
```

### A10a Event: `audio_stop`

This event is emitted by S01 (Core) to notify S13 (Partner)
that the audio stream transmission process is stopping.
This means the user has muted his microphone.

Message body format:

```ts
{
  "event": "audio_stop",
  "data": {
    "partner_id": string, // ID of the partner
    "conversation_id": string // ID of the conversation
  }
}
```

### A10a Event: `new_message`

This event is emitted by S01 (Core) to transmit
a new text message sent by the customer to S13 (Partner).
This message is sent by the customer.

Message body format:

```ts
{
  "event": "new_message",
  "data": {
    "partner_id": string, // ID of the partner
    "conversation_id": string, // ID of the conversation
    "message": {
        "id": string, // unique message ID
        "content": string, // message content
        "created_at": string // ISO 8601 timestamp e.g. "2024-01-01T12:00:00Z"
    }
  }
}
```

## A10b

**Direction:** S13 (Partner) → S01 (Core)

This API is based on RabbitMQ.

This API has the following methods and events.

### A10b Method: `consultation_response`

This method is called by S13 (Partner) to respond
to a consultation request sent earlier by S01 (Core).

Request body format:

```ts
{
  "method": "consultation_response",
  "params": {
    "conversation_id": string, // ID of the conversation
    "status": string // one of: "accepted", "rejected"
  },
  "id": string // equal to the request ID of the corresponding consultation_request
}
```

Response body format:

```ts
{
    "id": string, // the corresponding request id
    "result": {
        "status": string, // "success" or "error"
        "content": any // the return value of the called method"
    }
}
```

On success, the content's format would be the string `"OK"`.
This indicates that the consultation response
has been acknowledged by S01 (Core).

On failure (`status == 'error'`), the content would
reflect what is going on. If the failure is
caused by some `Exception`, the content should
be `str(e)` with `e` being the `Exception` instance
that was the culprit.

### A10b Event: `call_pickup`

This event is emitted by S13 (Partner) to notify S01 (Core)
that the human agent has picked up the call
(i.e. the conversation status in Partner's Consultation Service's
database is now `HUMAN_AGENT_CALLING`).

This corresponds to the `call_start` event
sent earlier by S01 (Core).

Message body format:

```ts
{
  "event": "call_pickup",
  "data": {
    "conversation_id": string // ID of the conversation
  }
}
```

### A10b Event: `call_end`

This event is emitted by S13 (Partner) to notify S01 (Core)
that the human agent has ended the call
(i.e. the conversation status in Partner's Consultation Service's
database is now `HUMAN_AGENT_TEXTING`).

Message body format:

```ts
{
  "event": "call_end",
  "data": {
    "conversation_id": string // ID of the conversation
  }
}
```
